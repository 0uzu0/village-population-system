# 数据库设计说明

数据库：MySQL 8，字符集 utf8mb4，存储引擎 InnoDB。

## 表清单（21 张业务表 + 迁移版本表）

| 表名 | 说明 | 关键点 |
|------|------|--------|
| `sys_user` | 用户表 | `username` 唯一，`password_hash` 存 bcrypt，`is_admin` 区分管理员 |
| `sys_role` | 角色表 | 仅两类：系统管理员、普通用户 |
| `sys_user_role` | 用户角色关联 | 联合唯一 |
| `sys_permission` | 权限表 | `code` 唯一 |
| `sys_role_permission` | 角色权限关联 | 联合唯一 |
| `grid` | 网格表 | `grid_no` 唯一 |
| `family` | 家庭表 | `family_no` 唯一，`head_person_id` 户主 |
| `person` | 人员档案表 | `person_no`、`id_card` 唯一 |
| `family_member` | 家庭成员关联 | `(family_id, person_id)` 唯一 |
| `tag_category` | 标签分类 | `code` 唯一 |
| `tag_definition` | 标签定义 | `code` 唯一，含颜色/对象类型等 |
| `person_tag` | 人员标签关联 | 生效/失效日期、状态、审核人 |
| `family_tag` | 家庭标签关联 | 同上 |
| `person_change_log` | 人员变更记录 | 旧值/新值 |
| `tag_change_log` | 标签变更记录 | 动作、操作人 |
| `excel_import_task` | 导入任务 | `batch_no` 幂等唯一；`task_type` 区分「人口档案 / 重点人群名单」导入 |
| `excel_import_error` | 导入错误记录 | 行号、错误信息、原始行 |
| `import_pending` | 导入待核查记录 | 身份证为空/非法的行，`status` 待核查/已入库/已忽略 |
| `export_task` | 导出任务 | 状态、结果文件 |
| `file_info` | 文件信息 | 存储路径 |
| `audit_log` | 审计日志 | 请求参数（凭证类脱敏） |
| `sys_dict` | 系统字典 | `(dict_type, dict_value)` 唯一 |
| `schema_migrations` | 迁移版本 | 记录已应用版本 |

## 敏感字段存储

- **身份证号**：`id_card`（VARCHAR(18) 明文存储，唯一索引用于查重）。
- **手机号**：`phone`（VARCHAR(20) 明文存储）。
- **密码**：`password_hash` 使用 bcrypt 哈希，数据库不存明文密码。

## 索引与查询优化

- 常用查询字段均建索引：`name`、`grid_id`、`family_id`、`status`、`birth_date`、`gender`。
- 标签筛选：`person_tag(person_id, tag_id)`、`person_tag(tag_id)` 索引，配合 `EXISTS` 子查询实现交集/并集，避免 N+1。
- 列表接口全部分页（默认 20 条，最大 200），禁止一次加载全量。
- 列表页标签展示：按页内人员 ID 批量查询标签后内存归组，避免 N+1。

## 统计口径

- 总人口（工作台展示口径）= 户籍人口 + 流动人口（两者互斥，见下）；`/statistics/dashboard` 仍返回 `totalPopulation`（在册档案数，迁出/死亡不计入）作为参照字段。
- 人员状态（V007 起）：`NORMAL` 正常 / `MOVED_IN` 迁入 / `MOVED_OUT` 迁出 / `DEAD` 死亡，另有 `status_date` 记状态生效日期（死亡日期、迁出日期）。原 `CANCELLED`（注销）已取消，存量数据迁移为 `DEAD`。
- 死亡、迁出一律**变更状态、不删除档案**：档案、标签与变更记录全部保留，自动从人口统计与重点人群名单中退出，可随时改回；删除只用于清理导入产生的重复/错误数据。
- 各标签人数 = 有效关联去重人数，**存在交叉不可相加**。
- 户籍人口 `HUKOU_POP` 与流动人口 `FLOATING_POP` **互斥不存在交叉**（v2.1.0）：流动人口 = 户籍不在本村、暂住本村的人员；打标签三处入口（建档/编辑标签同步、单个加标签、批量加标签）按「户籍优先」互斥，`V017` 修复存量；统计侧流动人口再按「排除持有户籍标签」兜底。总人口 = 户籍人口 + 流动人口。
- 低保分两级：家庭级 `LOW_INCOME_FAMILY`（家庭数）与个人级 `LOW_INCOME_PERSON`（人数），口径不同不混用。
- “五保户”为历史名称，正式标签用“特困供养对象”，以 `alias` 字段保留旧称。

## 数据库迁移

- 采用版本化迁移脚本（`backend/src/db/migrations/Vxxx__*.sql`），后端启动时自动执行，`schema_migrations` 表记录版本，保证幂等。
- 升级前必须备份，迁移不可逆（详见「更新与回滚说明」）。
