# 更新与回滚说明

## 一、镜像版本管理策略

| 标签 | 含义 | 是否可覆盖 |
|------|------|-----------|
| `latest` | main 分支最新稳定构建（开发预览用） | 是 |
| `sha-<短哈希>` | 每次提交对应的唯一镜像 | 否（随提交不可变） |
| `v1.0.6` | **当前正式版本**（不可变） | 否 |
| `v1.0.5` | 历史正式版本（不可变） | 否 |
| `v1.0.4` | 历史正式版本（不可变） | 否 |
| `v1.0.3` | 历史正式版本（不可变） | 否 |
| `v1.0.2` | 历史正式版本（不可变） | 否 |
| `v1.0.1` | 历史正式版本（不可变） | 否 |
| `v1.0.0` | 历史正式版本（不可变） | 否 |
| `v1.0` / `v1` | 主版本/次版本指针 | 是（指向最新次版本） |

- **开发镜像**：`latest`、`sha-<哈希>`，用于联调与预览。
- **正式发布镜像**：`vX.Y.Z`，不可变，用于生产。
- 生产环境 `.env` 中的 `VERSION` 应固定为 `vX.Y.Z`，禁止长期使用 `latest`。

## 二、升级流程

```bash
cd deploy
./scripts/backup.sh              # 1. 备份数据库与附件（必须，两份成对）
VERSION=v1.1.0 docker compose pull frontend backend   # 2. 拉取新镜像
./scripts/update.sh v1.1.0       # 3. 一键：备份→拉取→重启→健康检查
```

或手动：

```bash
./scripts/backup.sh
VERSION=v1.1.0 docker compose pull frontend backend
sed -i 's/^VERSION=.*/VERSION=v1.1.0/' .env
VERSION=v1.1.0 docker compose up -d frontend backend
./scripts/healthcheck.sh
```

数据库结构迁移在后端启动时自动执行（幂等，通过 `schema_migrations` 表记录已应用版本）。

## 三、回滚流程

```bash
./scripts/rollback.sh v1.0.0     # 回滚应用镜像
./scripts/healthcheck.sh
```

## 四、数据库迁移后的回滚限制（重要）

- **应用镜像**：可随时回滚到任意旧版本，镜像不可变，随时可用。
- **数据库结构**：迁移不可逆。若新版本迁移修改了表结构且旧应用不兼容，回滚镜像无法解决，必须**从备份恢复数据库**：

```bash
# 先停掉后端，避免回滚期间写入
docker compose stop backend
# 从升级前的备份恢复
./scripts/restore.sh backups/village_population_<升级前时间戳>.sql.gz
# 重启后端
docker compose up -d backend
```

## 五、升级前检查清单

1. 已备份数据库并确认备份文件非空。
2. 已阅读新版本的数据库迁移脚本（`backend/src/db/migrations/`）。
3. 已准备旧版本镜像标签，便于回滚。
4. 业务低峰期执行，并在升级后验证核心功能（登录、人口列表、标签筛选、统计）。
